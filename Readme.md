## Methods Explained

### Data preprocessing

The current workflow checks missing values, drops identifier/target columns from the feature table where appropriate, fills missing `parental_education` values with the mode, and encodes selected categorical variables. It then separates features (`X`) from the target (`y`) and creates an 80/20 train/test split with `random_state=42`.

### Linear Regression

Linear Regression estimates a continuous `final_exam_score` from the available input features. It is the main regression model in the initial notebook sections.

### Cross-validation

The notebook uses shuffled 5-fold cross-validation with a fixed random seed and R² scoring. Each fold acts as a validation fold once. The notebook reports fold scores, their mean, and standard deviation.

### Regression evaluation

- **MAE:** average absolute prediction error; lower is better.
- **MSE:** average squared prediction error; lower is better and larger errors receive more weight.
- **R²:** compares model performance with a mean-target baseline; values closer to 1 generally indicate better fit, while negative values can indicate performance worse than that baseline on the evaluated data.

### Logistic Regression

The classification section predicts `final_grade`. This is a classification task even though the algorithm's name contains “Regression.”

### Ridge Regression

Ridge Regression adds an L2 penalty to reduce the magnitude of model coefficients. The notebook scales features before fitting Ridge.

### Principal Component Analysis (PCA)

PCA transforms scaled features into orthogonal components ordered by explained variance. The notebook explores cumulative explained variance to understand possible dimensionality reduction.

### Naive Bayes

The notebook introduces three classifiers:

- **Gaussian Naive Bayes** — commonly used with continuous-valued features.
- **Multinomial Naive Bayes** — designed for non-negative count/frequency-style features.
- **Bernoulli Naive Bayes** — designed for binary-valued features.

Their suitability depends on how the dataset features are represented and transformed.

### Support Vector Machine (SVM)

The notebook uses an SVC with an RBF kernel to model potentially non-linear class boundaries. Feature scaling is important for SVMs.

### K-Means clustering

K-Means is applied to `study_time_hours` and `attendance_percent`. The notebook standardizes these two features and examines within-cluster sum of squares (inertia) over several candidate values of K using the Elbow method. The chosen cluster count should be justified by the plotted results and, where possible, additional validation.

## Important Implementation Notes

These are review points observed in the uploaded notebook; they should be checked before presenting the project as a validated experiment.

1. **Feature encoding:** `LabelEncoder` is used on input categorical columns. For nominal features, `OneHotEncoder` inside a scikit-learn `ColumnTransformer` is generally a safer choice because integer labels can imply an artificial order.
2. **Consistent preprocessing:** Fit preprocessing only on the training data and apply the fitted transformations to validation/test data. A scikit-learn `Pipeline` helps avoid leakage and keeps transformations consistent.
3. **Cross-validation leakage:** The T3 cross-validation cell evaluates `X` and `y` after encoding/filling values on the full dataset. For a more rigorous estimate, place preprocessing inside a pipeline and cross-validate the pipeline.
4. **Scaling:** The initial `StandardScaler` transformation is commented out. Scaling is especially important for SVM, PCA, and regularized models; use a pipeline so scaling is fitted on training folds only.
5. **T5 dependencies:** The T5 cell's training code is commented out and its metric calculations use `y_pred` from earlier cells. Running it independently may evaluate stale predictions or fail if variables are missing. Train the model and create predictions inside the T5 section.
6. **Target separation:** Keep `final_exam_score` out of the classification feature matrix when predicting `final_grade`, as the notebook currently attempts to do. Confirm that no other target-derived columns leak the answer.
7. **Classification encoding:** Use a separate, appropriate encoder for each categorical feature or use `OneHotEncoder`; avoid reusing a single label encoder instance across unrelated feature columns when inverse mappings may be needed.
8. **Model comparisons:** Compare models using the same train/test split or the same cross-validation folds, and report the metric used.
9. **Clustering interpretation:** K-Means groups are exploratory patterns, not objectively defined student types. Do not attach unsupported labels or causal interpretations to clusters.
10. **Reproducibility:** Record package versions, dataset provenance, random seeds, and the exact split/evaluation procedure.
